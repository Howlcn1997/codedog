# Code Dog 用户指南

Code Dog 是一个本地优先的桌面项目管理中心。它不会接管你的代码仓库，而是把分散在电脑上的 Node.js、Go、Python 和其他项目汇总到同一个工作台，方便搜索、打开、检查环境与管理磁盘占用。

本指南适用于第一次使用 Code Dog 的用户。

## 1. 快速开始

### 第一步：启动应用

从 [GitHub Releases](https://github.com/Howlcn1997/codedog/releases/latest) 下载 macOS 版本并安装，然后启动 Code Dog。

如果你只想先看看界面，可以进入「设置 → 通用」，选择「查看演示」。演示模式不会读取或修改本地项目。

### 第二步：选择项目根目录

首次启动时，点击「选择项目根目录」，指定一个用于统一存放项目的文件夹。

Code Dog 默认提供公司项目、个人项目和临时项目三个分组。复制、移动或克隆的项目会进入根目录下对应的分组目录；使用“登记项目”时，源码仍保留在原位置。

> 已经导入项目后不能直接切换根目录，以免已有路径失效。需要迁移时，请先导出备份并逐步处理项目。

### 第三步：导入第一个项目

点击右上角「导入项目」，然后选择一种来源：

| 来源       | 适合场景                     | 操作方式                               |
| ---------- | ---------------------------- | -------------------------------------- |
| 已有文件夹 | 导入电脑上已有的单个项目     | 复制、移动或原地登记                   |
| Git Clone  | 从远程仓库获取项目           | 输入 HTTPS 或 SSH 仓库地址             |
| 批量扫描   | 一次发现某个目录中的多个项目 | 扫描最多深入 4 层、最多发现 300 个项目 |

导入前可以设置项目名称、分组和标签。

#### 复制、移动和登记有什么区别？

- 「复制到根目录」：在 Code Dog 根目录中创建副本，原文件夹保留。
- 「移动到根目录」：把原文件夹移动到 Code Dog 根目录。原路径将不再存在，已有终端或 IDE 窗口可能需要重新打开。
- 「登记项目（保留原路径）」：只把项目加入管理，不复制也不移动源码。
- 「Git Clone」：把远程仓库克隆到所选分组目录。

跨磁盘导入时请使用复制方式。批量移动项目时，可以勾选「复制 Claude Code 聊天记录到新路径」；旧路径中的记录会保留，已有会话不会被覆盖。

## 2. 认识标准模式

标准模式是完整的项目管理工作台，主要分为三部分：

- 左侧导航：全部项目、最近打开、收藏、各项目分组、存储空间和已归档项目。
- 中间区域：搜索、筛选、排序以及列表或卡片视图。
- 右侧详情：项目路径、Git 状态、开发环境、依赖、磁盘占用和备注。

点击项目即可查看详情。使用项目中的打开按钮，可以在默认 IDE 中打开项目。

## 3. 搜索和筛选项目

在顶部搜索框输入关键词。Code Dog 可以搜索：

- 项目名称和搜索别名
- 项目路径
- 标签、描述和备注
- Git 远程仓库地址
- 项目根目录 README
- 依赖名称

项目名称支持子序列模糊匹配。搜索结果下方会显示命中原因，帮助你判断关键词来自 README、依赖、路径还是其他信息。

还可以组合使用分组、技术栈、标签和依赖状态筛选，并按最近打开、名称或最近导入排序。

README、项目声明和依赖文件发生变化时，Code Dog 会自动刷新对应项目的本地搜索索引。也可以点击搜索框旁的刷新按钮手动更新。

常用快捷键：

- `⌘/Ctrl + K`：聚焦搜索框。
- `Escape`：清空当前搜索。

## 4. 使用精简模式和全局启动器

点击标题栏中的「精简模式」，可以切换到适合快速启动项目的紧凑界面。Code Dog 会记住选择，下次启动时恢复该模式。

在任意应用中按 `⌘/Ctrl + Shift + Space`，可以呼出全局项目启动器；当启动器已经处于前台时，再按一次会将它收起。

精简模式支持全键盘操作：

| 按键          | 操作                                   |
| ------------- | -------------------------------------- |
| `⌘/Ctrl + K`  | 聚焦搜索框                             |
| `↑` / `↓`     | 选择上一个或下一个项目                 |
| `←` / `→`     | 切换打开方式                           |
| `Enter`       | 执行当前打开动作                       |
| `Escape`      | 先清空搜索和筛选；再次按下时收起启动器 |
| `Shift + F10` | 打开所选项目的右键菜单                 |

精简模式提供“本周项目”“有未提交修改”“公司后端”等快捷筛选，也可以组合搜索词、分组、技术栈、标签和排序规则后点击「保存当前」。最多可保存 20 组筛选条件。

导入、编辑、依赖安装和存储管理仍需在标准模式中完成。

## 5. 打开项目

Code Dog 支持以下打开动作：

- 在默认 IDE 中打开
- 在终端中打开
- 在文件管理器中打开
- 打开远程仓库页面（项目存在远程地址时）
- 复制项目绝对路径

默认支持 Cursor、Visual Studio Code、WebStorm、GoLand 和 PyCharm。可在「设置 → 打开方式」中设置默认 IDE，也可以编辑单个项目，为它指定独立 IDE。

在标准列表、卡片或精简列表中右键项目，可以临时选择另一款 IDE；这不会修改项目的默认设置。默认终端可以选择系统终端或 Warp，使用 Warp 前需要先在电脑上安装它。

## 6. 整理项目

### 分组与标签

除了内置分组，还可以通过侧边栏旁的新增按钮或导入窗口创建自定义分组。新分组会出现在导入、编辑和筛选选项中。

标签适合标记客户、业务、状态或用途，例如 `frontend`、`internal`、`prototype`。导入项目时可以复用已有标签，也可以在编辑项目时调整。

### 编辑项目信息

选择项目后点击编辑，可以修改显示名称、分组、标签、搜索别名、备注和项目独立 IDE。

修改显示名称或分组只会更新 Code Dog 的管理信息，不会重命名或移动磁盘上的文件夹。建议为名称相近的项目设置唯一搜索别名，方便在全局启动器或命令行中准确打开。

### 收藏、归档与移出管理

- 收藏：将常用项目集中显示在「收藏」中。
- 归档：从日常项目列表隐藏，之后可以在「已归档」中恢复。
- 移出管理：只删除 Code Dog 中的项目记录，项目源码和依赖会完整保留在原目录。

## 7. 查看 Git 和开发环境

项目详情的「概览」会显示当前 Git 分支、未提交修改数量、`origin` 远程仓库地址、检测到的技术栈、运行时、包管理器、依赖声明文件和安装位置。

这些 Git 信息从本地仓库读取，Code Dog 不会自动执行 `git fetch`。

目前可识别：

- Node.js：`package.json` 及 npm、pnpm、Yarn
- Go：`go.mod`、`go.work`
- Python：`pyproject.toml`、`requirements.txt` 及 uv、Poetry、pip

点击开发环境旁的「检查」，可以重新检查本机运行时与包管理器。

## 8. 查看和安装依赖

进入项目详情的「依赖」标签页，可以查看已解析的依赖名称、声明版本、所属技术栈和依赖类型。

点击「安装依赖」或「同步依赖」后，Code Dog 会先用原生确认框展示即将执行的命令。确认后可能执行：

- npm、pnpm 或 Yarn 安装
- `go mod download`
- `uv sync`
- `poetry install`
- 项目 `.venv` 中的 pip 安装

执行输出会显示在底部「操作日志」中。

> 安装操作可能更新锁文件并运行依赖包的安装脚本。确认前请检查命令。界面中的“依赖就绪”只表示对应依赖目录存在，不保证锁文件完全一致或运行时版本兼容。

## 9. 分析和清理存储空间

在左侧进入「存储空间」。Code Dog 会按项目分别统计源码与其他文件、本地依赖和项目总占用。扫描不会跟随符号链接，也不会把 Go、npm 等共享缓存计入项目空间。

如需释放空间：

1. 点击「重新扫描」。
2. 勾选一个或多个项目。
3. 查看预计可释放空间。
4. 点击「清理所选项目依赖」。
5. 在 Code Dog 确认框中核对将删除的目录和空间大小。确认框默认展示前 5 个目录，可展开查看完整清单。

清理仅针对项目范围内的 `node_modules`、`.venv` 和 `venv` 目录，不删除源码。之后可回到项目详情重新安装依赖。

## 10. 设置与备份

「设置」包含以下内容：

- 通用：项目根目录、全局启动器快捷键、macOS 命令行工具和演示数据。
- 外观：跟随系统、亮色或暗黑主题，以及标准/精简界面模式。
- 打开方式：默认 IDE，以及系统终端或 Warp。
- 数据：导出项目管理数据备份。

导出的备份包含项目路径、分组、标签和备注等管理信息，不包含项目源码。目前尚未提供备份恢复功能。

## 11. 使用命令行工具（macOS）

在「设置 → 通用 → 命令行工具」中点击安装。命令默认写入 `~/.local/bin/codedog`。

如果终端找不到 `codedog`，请把以下内容加入 `~/.zshrc`，然后重新打开终端：

```sh
export PATH="$HOME/.local/bin:$PATH"
```

常用命令：

```sh
codedog add .
codedog list
codedog list backend
codedog open my-project
codedog path my-project
```

- `add`：原地登记目录，不移动源码。
- `list`：列出项目，也可以使用一个关键词筛选。
- `open`：按名称或别名使用项目默认 IDE 打开。
- `path`：输出项目的绝对路径，适合与其他终端命令组合使用。

命令行和桌面端共用同一份项目数据，桌面端未运行时也可以使用。如果名称或关键词匹配多个项目，Code Dog 会列出候选项；为项目设置唯一别名后即可准确调用。

## 12. 数据、隐私与使用边界

Code Dog 的管理数据保存在 Electron 的 `userData` 目录中。macOS 通常位于：

```text
~/Library/Application Support/codedog/projects.json
```

项目源码保存在你选择的位置，不会自动上传。Code Dog 不启用渲染进程 Node.js 集成；本地操作通过隔离的白名单接口完成，命令使用参数数组调用，不会把项目名称或路径拼接进 shell 命令。

需要留意以下边界：

- 路径失效的项目会显示错误，需要重新导入或移出管理。
- 跨磁盘移动项目时应改用复制方式。
- 复杂 TOML、外部 requirements 引用、Poetry 外部虚拟环境和 monorepo 子包可能无法完整展示。
- Code Dog 尚不支持自动依赖升级、共享依赖缓存清理、整体根目录迁移、备份恢复和批量编辑。
- Windows 和 Linux 保留了打包配置，但当前主要验证平台是 macOS。

## 13. 常见问题

### 为什么搜索不到 README 中刚加入的内容？

等待片刻让索引自动更新，或点击搜索框旁的刷新按钮。如果项目路径已经失效，需要先重新导入项目。

### 为什么项目显示“依赖待安装”？

Node.js 项目通常表示缺少 `node_modules`，Python 项目通常表示缺少 `.venv`。进入项目的「依赖」标签页检查命令后再安装。

### 清理依赖后项目还能使用吗？

源码和依赖声明不会被删除，但运行或构建项目前需要重新安装依赖。

### 为什么无法在某个 IDE 或 Warp 中打开？

请先确认对应应用已经安装。IDE 命令或应用名称还需要能够被当前系统识别。

### 如何只从 Code Dog 中移除项目？

打开项目详情并选择「移出管理」。该操作只移除管理记录，不会删除磁盘文件。
